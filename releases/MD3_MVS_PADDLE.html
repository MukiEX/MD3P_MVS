    The idea

    Taito's F3 board reads its "sensor" spinners on two plain input lines, the same kind a joystick uses. Puchi Carat on F3 is the reference for how a spinner puzzle game should feel, with a knob that moves the paddle directly and menus that tick one item per notch. These patches bring that to three Neo Geo games without taking any buttons away. The spinner uses only the joystick's LEFT and RIGHT lines, so UP, DOWN and A to D still work.

    Two wires, one knob

    A spinner is a quadrature encoder. It drives two lines, A and B, that switch a quarter-cycle apart. Each change on either line is one count, and which line moves first gives the direction. In this patch, as on F3, LEFT is A and RIGHT is B.

    Reading it on a Neo Geo

    The Neo Geo has no hardware counter for this. The game only sees whatever LEFT and RIGHT are at the moment it reads them. A game reads its controls once a frame, about 60 times a second, and a quick turn can produce far more edges than that.

    So the patch uses the video chip's raster timer, the IRQ2 interrupt that some games use for mid-screen effects. None of these three needed it for that. The timer is set to fire every 4 scanlines, about 3,900 times a second. On each tick, a few instructions read both ports, look up the previous and current phase in a 16-entry table, and add +1, −1 or 0 to a running count for each player. If both lines changed between two samples, that sample is ignored because its direction can't be known. This is the same rule as the F3 MiSTer core's spinner decoder.

    The game's own code keeps writing the video chip's mode register. Every one of those writes is routed through a small stub that keeps the timer bits set. Without that, the first write would quietly switch sampling off.

    Knowing a spinner is there

    A lever can't press LEFT and RIGHT together, but a spinner passes through that state every few counts. The first time a port reads both at once, it's marked as a spinner and sampling starts. Until then the patched game behaves exactly like the original, and a lever on the other port stays a lever.

    Turning counts into play

    Magical Drop III

    • A virtual paddle. The knob moves an invisible paddle across the field, like Puchi Carat's: 4 counts per column, clamped at the walls. A column edge has to be passed by one extra count before it counts. After a short rest, the paddle settles back to the middle of its column, so every move from rest takes the same turn and small one-column moves are easy to repeat. The clown then walks to that column at the game's own pace.
    • Glide and highlight. The clown and its aim line are drawn where the paddle actually is, so they glide instead of jumping. The target column pulses between darker and lighter. That comes from shaded copies of the balloon palettes in palette slots the game never uses, which the sprite engine swaps in for that column's balloons. The copies are refreshed a couple per frame so they follow the game's fades without slowing it down.
    • Optional magnet. Over a column whose bottom balloon matches the colour in hand, the paddle moves at half speed so it's easy to stop there.
    • Menus. Knob motion becomes one LEFT/RIGHT or UP/DOWN tap per 16 counts and is written into the game's own input records, so every menu reacts as if the lever were tapped. Character select walks the cards in reading order, and name entry turns at 4 counts per letter.
    • Extras. MOUSE SPEED (x0.25 / x0.5 / x1) is a new item in the home option menu. The hidden characters are always unlocked.

    Pop 'n Bounce

    This game already supports SNK's analog dial. It reads the dial's position each frame and turns the change into paddle speed. The patch simply feeds the spinner's count into those reads and switches the game into its own PADDLE mode once a spinner is seen. The physics and feel are the game's own.

    Puzzle Bobble 2

    The launcher's angle is a fixed-point number from −60 to +60 steps. Each count moves it one step, with fractions carried over between frames. The crank animation follows along. The crank's tick sound plays as it does with the lever, but at most once every 4 frames, because the game sends only one sound byte per frame and a fast spin would otherwise hold up the bubble sounds. Menus, the puzzle route map and difficulty select step one item per notch. There was no free space in the 1 MB program ROM, so the patch adds a second megabyte, which the hardware already maps at CPU address $200000.

    How it was made

    1. A test bench. Development used a headless Neo Geo emulator (a modified Geolith) driven from Python. Its simulated spinner produces real quadrature edges with the right timing inside each frame, including MiSTer's 1 ms USB input steps. It can also watch memory, log sounds and video writes, save states, and fault on misaligned memory accesses the way real hardware does.
    2. Finding the game's variables. Holding LEFT or RIGHT and comparing memory frame by frame turned up the values that move: the clown's column, the dial position, the launcher angle. A disassembler then found the code that reads the controls and acts on them. Those are the patch sites.
    3. Small, guarded patches. Each change replaces a few instructions with a jump into new code, and the build first checks that the original bytes are there. New code goes into unused ROM space, and its working memory sits where the game never writes.
    4. Tuning by feel. Rates, the edge buffer, re-centring, the glide and the highlight were settled by playing on MiSTer, with each idea checked on the test bench first.
    5. Catching faults. Scripted runs check the menus, play, and the lever path on unpatched ports, and long soak runs check stability. One bug only showed up on MiSTer: a stub that saved half a register inside an interrupt. The emulator turned out to be quietly rebooting from the same fault, and switching patch sites off one at a time found it.

    This page

    The patcher carries only the bytes the patches change, never ROM data. It recognises your file by the CRC of its program ROM, writes the changes (the program ROM is stored byte-swapped in a .neo, so each byte goes to its swapped position), sets the name MiSTer shows, and checks the result's CRC against the build that was tested before saving it.
